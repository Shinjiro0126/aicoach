# 提案書: 「旗の日」を離脱点から継続の起点に変える

作成日: 2026-08-28 / ステータス: 承認済み・未実装(実装は別途、優先順位に沿って進める)

週の終わり(旗の日)にユーザーをアプリから離脱させず継続させるための施策パッケージ。言葉のルールは [tone-of-voice.md](tone-of-voice.md)、世界観は [brand.md](brand.md) に従う。

---

## 0. サマリー

現状、週の終わり(旗の日)は「第N週の旗に、たどり着きました。」という1行で終わり、翌週は前日コピーの同じタスクが続くだけ。ユーザー視点では**「旗にたどり着いても何も起きず、翌週は先週の劣化コピー」**であり、週の節目が達成感の頂点ではなく離脱点になっている。

本提案は、旗の日を **「締め(祝う)→ 見立て(観察)→ 宣言(次週の一歩)」** の3拍子の体験に変え、次週の初日を fresh start として再スタートさせる。**締め体験は無料、AIによる深掘り(見立ての手紙・リプランの意図全文)はプレミアム**に置く。

### 現状の空白地帯(実装調査の結果)

1. **旗の日にトリガーされる処理がゼロ** — ホーム提出後の1行と飛び石ヘッダのみ。`celebration.tsx` は旗の日を知らない
2. **第2週以降の「今日の一歩」はAI生成でなく前日コピー** — `repo.ts` の `ensureTasksForDate` → `getLatestAction`。毎日同じ文言が無限に続く
3. **第5週以降は週フォーカスが第4週で凍結** — weeklyFocus は4週分のみ。長期目標ほど空洞化
4. **週次リプランが存在しない** — AIの `/v1/plan` はオンボーディング1回きり(行動は7日分のみ)
5. **週の節目の通知が皆無** — 通知は日次2本の固定文のみ
6. **ペイウォールの「週次レビュー」は未実装** — 観察手帳はプレミアム+データ2週+手動オープンの三重ゲートで実質到達不能
7. **期日到達後の終端がない** — `status:'done'` を書くコードが存在せず、通知が永久に鳴り、次目標への導線もない

### 追い風(すでにある資産)

- `celebration.tsx` は `week: WeekFlagInfo` を受け取り済み → 旗の日判定の材料は手元に揃っている
- `insight-stats.ts` の週次統計の純関数群(歩いた日/報告した日/おやすみ/復帰力)は無料で使える → AIなしで週まとめカードが組める
- `expo-notifications` の WEEKLY トリガーで旗の日通知はローカルだけで実現できる
- コーチAIには今週フォーカス・今日のタスクを渡す実装が済んでいる

## 1. 行動科学の根拠マップ

| 原理 | 内容 | 使う施策 | ブランド原則との整合 |
|---|---|---|---|
| ピーク・エンドの法則 | 体験の記憶は「頂点」と「終わり」で決まる | A-1 旗の日セレモニー | 祝いの場面は「少し砕けてよい」 |
| Fresh Start Effect | 節目は「新しい自分」の感覚を生み、行動開始率が上がる | A-3 / B-1 / B-2 / C-1 | まっさらな7日を責めずに提示。過去週の失敗は蒸し返さない |
| 実装意図 | 「いつ・何をやるか」の事前言語化で実行率2〜3倍 | A-2 歩幅宣言(3択) | 選択肢は3つ、最終決定はユーザー |
| 目標勾配効果 | ゴールが近いほど頑張れる(週=7日は実装済み) | A-1 / D-1 | 既存設計の延長 |
| 損失回避(ストリーク) | 積み上げを失いたくない心理 | C-1(事実提示まで)・救済ルールの強調 | **煽りは禁止**。「守られている」方向でのみ使う |
| 授かり効果 | 最初から進捗があると完遂率が上がる | B-1(「来週の7日分はもう用意してあります」) | 先回りして道を整える=経験者コーチの人格 |
| ツァイガルニク効果 | 未完了のものは記憶に残る | A-3 次週プレビュー | 予告は1つに絞る |

**ダークパターン非採用の明示**: ストリーク喪失カウントダウン、「今戻らないと消える」通知、連続未達の可視化強調は、責めないブランド原則と禁止語辞書に反するため一切使わない。

## 2. 施策の全体像

体験の時系列: **旗の日の提出 → [A-1 セレモニー] → [A-2 歩幅宣言] → [A-3 次週プレビュー] → (裏で B-1 リプラン) → 翌朝 [C-1 通知] → 新しい週**

### A. 週の締め: 旗の日セレモニー(無料)

#### A-1. 旗の日限定の祝い演出 [規模M]

- **狙い**: ピーク・エンド。週7日の終わりを毎日の提出祝いより一段上の体験にする
- **トリガー**: ホーム提出時に旗の日なら、通常の `Celebration` の代わりに旗の日バリアントを表示。`progress.ts` に純関数 `isFlagDay(startKey, today)` を追加して判定
- **体験の流れ**:
  1. 旗が立つアニメーション + Hotori `applaud` ポーズ(毎日の `celebrate` と差別化)
  2. 見出し: 「第3週の旗に、たどり着きました。」
  3. 週のまとめ(端末内の `daily_reports` から集計、AI不要):
     > 「この7日で、歩いた日が5日、報告した日が1日、おやすみが1日。できなかった日も、道のうちです。」
  4. `buildTeaser()`(無料・決定的)のひとこと観察:
     > 「あなたは火曜に強い。直近3週、火曜の歩みがいちばん確かです。」
  5. ボタン: 「来週の歩幅を決める」(→ A-2)/「そのまま閉じる」
- **無料/プレミアム**: 全部無料。**ペイウォールの「週次レビューで1週間をまとめて振り返り」という未実装の約束をここで果たす**(信頼の回復)
- **変更箇所**: `src/components/celebration.tsx` / `src/app/(tabs)/index.tsx` / `src/lib/progress.ts`

#### A-2. 来週の歩幅宣言(実装意図・3択) [規模S]

- **体験**: セレモニーの最後にホトリが問う:
  > 「来週の歩幅を決めましょう。最後に選ぶのは、あなたです。」
  > 選択肢: **「この歩幅のまま」/「少し軽くする」/「少し広げる」**
- **実装**: 選択を `stores/app.ts` に永続化(`nextWeekPace: 'keep' | 'lighter' | 'wider'`)。翌週の `ensureTasksForDate` が main タスク文言を調整(lighter → 5分版など)。B-1 導入後はリプランのプロンプト入力になる
- **無料**(AI呼び出しゼロ)

#### A-3. 次週プレビュー(オープンループ) [規模S・A-1に内包]

> 「第4週の道を整えておきました。明日の朝、最初の石で待っています。」

第4週まではローカルの `weeklyPlans` から次週フォーカスを表示。B-1 導入後はリプラン結果の予告になる。

### B. 次週の始まり: 週次リプラン(fresh start の実体)

#### B-1. `/v1/replan` — 週1回のAIリプラン(無料) [規模L]

- **狙い**: 空白地帯2・3・4(前日コピー、第5週凍結、リプラン不在)を一挙に解消。fresh start は気分だけでは続かず、**翌週の中身が実際に新しい**ことが必要
- **仕様**:
  - 新エンドポイント `POST /v1/replan`(`proxy/src/index.ts`+`REPLAN_SYSTEM` を `proxy/src/prompts.ts` に追加)
  - 入力: goalTitle / why / category / weekNo / 前週フォーカス / 前週の main 行動一覧 / 週次統計 / A-2 の歩幅宣言
  - 出力: `{ nextWeekFocus, dailyActions[7], flagMessage }`
  - 保存: `insertWeeklyPlans` を週追加に対応させ、`insertDailyActions` で次週7日分を書き込む(`ensureTasksForDate` の既存優先順位で自然に効く)
  - 発火: セレモニー中に裏で fire-and-forget。**失敗時は現行の前日コピーにフォールバック(劣化なし)**
- **プライバシー**: 送るのは `/v1/plan` が既に送る情報+AI自身が生成した行動文言+統計値のみ。**ユーザーの custom タスク・会話・ヒアリング回答は送らない**。サーバー保存なしの原則は維持
- **コスト明示**: 無料ユーザーにも週1回(月約4回/人)のAI呼び出しを追加。対話クォータ(1日10回)とは別枠
- **プレミアム線引き**: リプラン自体は無料。「なぜこの計画にしたか」のホトリの手紙全文はプレミアム(観察手帳に掲載)

#### B-2. 週初日の fresh start 演出 [規模S]

旗の翌朝、ホームの朝ひとことを週初日だけ切り替える:

> 「今日から第4週です。まっさらな7日を、いまの歩幅で歩きましょう。」

### C. 通知(ローカルのみ・追加は週1本まで)

押し付けない原則のため通知総量は増やしすぎない。

- **C-1. 旗の日通知(無料) [S]**: WEEKLY トリガーで旗の日の昼(朝・夜の既存通知と衝突しない時刻)に:
  > タイトル「今日は旗の日です」/ 本文「今週の旗が、すぐそこにあります。今週の歩みを、見に来てください。」
  >
  > ※ローカル通知は週番号を動的更新できないため「第N週」は入れない
- **C-2. 手帳更新通知(プレミアム) [S]**: 週初日の朝に「観察手帳を書き終えました。あなたの1週間の見立てが、手帳にあります。」
- **C-3. 観察手帳への導線接続 [S]**: セレモニーに手帳入口を常設。無料=ティザー1行+「ホトリの見立てを読む(プレミアム)」でペイウォールへ/プレミアム=手帳へ直行(開いた時点で新週の生成が走る既存ロジックが活きる)。手帳の週(初提出日起点)と旗の週(目標開始日起点)のズレ統一は「後で」

### D. 長期

- **D-1. 第5週以降の凍結解消**: B-1 が毎週フォーカスを生成するため自然解消。リプラン失敗週は直前週フォーカスを流用(現状動作と同じ)
- **D-2. 期日到達の終端体験 [M-L]**: `reached` 初回検知でゴールセレモニー(Hotori `hero` + 全期間の総括: 歩いた日数・止まって戻った回数・ベストストリーク)。選択肢は3つ:
  > 「旗じまいする(完了)」/「もう少しこの道を歩く(延長)」/「あとで決める」
  >
  > 「ゴールまで、歩き切りました。この道は、もうあなたのものです。次の道を探すのも、ここで少し休むのも、あなたが決めてください。」
  完了で `goals.status='done'` 書き込み(現在書き込むコードが存在しない)+通知停止+新目標オンボーディングへの導線。プレミアムは「卒業の手紙」
- **D-3. 期日超過ケア [M]**: 期日を過ぎたユーザーに「旗の立て直し」(延長/完了/新目標)を1回だけ提示。D-2 画面を再利用

## 4. 計測(PostHog / 決められたイベント名のみ・自由テキスト禁止)

| イベント | プロパティ(数値/boolean/enumのみ) | 測ること |
|---|---|---|
| `flag_day_reached` | weekNo, weekDoneCount(0-7) | 旗の日到達数(ファネル分母) |
| `flag_ceremony_closed` | weekNo, action('pace_selected'/'closed') | セレモニー完走率 |
| `next_week_pace_selected` | pace('keep'/'lighter'/'wider') | 実装意図の利用率・選好分布 |
| `weekly_replan_generated` | weekNo, fallback(boolean) | リプラン成功率・AI障害率 |
| `notebook_opened` | weekNo, premium, from('ceremony'/'tab') | 三重ゲート解消の効果 |
| `goal_completed` / `goal_extended` | totalDays, walkedDays | 終端体験の選択分布 |

**主要KPI**: 旗の日の翌週に3日以上提出したユーザーの割合(週跨ぎ継続率)。
副KPI: セレモニー→歩幅宣言の完走率、`notebook_opened` 経由の `paywall_viewed`。

## 5. やらないこと(検討して外した施策)

| 施策 | 外した理由 |
|---|---|
| ストリーク喪失を強調する通知 | 損失回避の煽り=ダークパターン。「連続記録が途切れました」は禁止語。救済ルールの思想と矛盾 |
| 会話ログのAI分析による週次レビュー | 会話のサーバー送信は禁止。/v1/insight の「統計値のみ」原則を崩さない |
| プッシュ通知による離脱ユーザーの呼び戻し | プッシュ基盤なし。サーバーがユーザー状態を知らない設計を守る |
| 毎日のAIタスク生成 | コストが週次の7倍。週次で7日分まとめて生成すれば十分。日中の変更はコーチ対話で吸収 |
| 週の締めのSNSシェアカード | シークレット・ジャーニー(人に見せない前提)と衝突 |
| バッジ・ランキング等の外的報酬 | 「責めない・比べない」と相性が悪い。祝いはホトリとの1対1で完結させる |
| 週次通知の複数本化 | 通知が1日3本になる日が生まれ「押し付けない」に反する。追加は週1本に抑える |
